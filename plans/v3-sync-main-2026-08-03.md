## Decisions carried over

**The font fix `ab66499598` had nothing to port.** v3-beta deleted the whole v2
babel extractor, so the `createExtractor`/`normalizeTernaries` half had nowhere
to land. Its `concatClassName` `font_` dedup merged on its own and is present.
The underlying parity gap (v3 bails the whole element rather than compiling a
conditional font variant) belongs to the engine lane.
`tests/fonts.web.test.tsx` pins what v3 does today.

**The media-state half of `a4ce4e9bdb` was deliberately not ported.** It puts
media containers on `globalThis`, and `static-tests/tests/loadTamagui.web.test.tsx`
asserts the opposite: the compiler's boundary copy of core must keep its own
`mediaQueryConfig`. The token half is ported through v3's existing global-config
channel. `mediaState.ts` is back to plain module-local containers; verified, no
`__tamaguiMediaShared` anywhere in the tree.

**Other resolutions.** Rewritten or renamed packages took the v3 side. The
PromoBanner removal was adopted and `Header.tsx` keeps v3 flat shorthand;
`hasBanner`, `bannerHeight`, and `PromoBanner` have no references left in
`tamagui.dev`. `code/sandbox` pinned to `one@1.21.13`, matching kitchen-sink and
tamagui.dev. All 164 public workspace packages sit on 2.6.3.

## Fixes made while validating this sync

- `735e19a93c` **kitchen-sink `TooltipStaticClobberCase`.** main added this
  usecase (`d1a833b4d5`) in v2 syntax and v3-beta never had it, so the merge
  imported it verbatim and root typecheck failed with three `TS2322`s. Ported to
  v3 flat syntax against its v3 sibling `TooltipToolbarRowCase.tsx`.
- `175fa50176` **`_withStableStyle` media condition tuples.** A real gap the
  merge created: main's `5bd95d0eb3` (Fixes #4133) had a runtime half and a test
  half, and the merge took main's test while keeping v3's copy of
  `code/core/web/src/_withStableStyle.tsx`, so the fix itself was dropped and
  only its test came across. The `Array.isArray(expr)` branch is ported.
- `3cfb870c73` **CLI bundled v6 grammar snapshot.** See below.
- `d88ac24ce6` **`TooltipStaticClobber.animated` position reader.** main's test
  read the tooltip's x from `getComputedStyle(el).transform`. v3 writes position
  to the CSS `translate` property instead, so on the css and reanimated drivers
  the recorder sampled the wrong thing and reported teleport-sized jumps. Ported
  to the same reader the sibling `TooltipToolbarRow` suite already uses, and
  moved the jump threshold from main's `60` to that suite's `150`, which is the
  number calibrated against v3's drivers. Green on css, reanimated, and motion;
  native skips by design.

  That threshold change was validated by a negative control rather than assumed
  safe: with `withStaticProperties` reverted to its pre-`d1a833b4d5` body, the
  test fails on `expect(ids.size).toBe(1)` with `Received: 2`. The node-identity
  assertion, not the jump threshold, is what actually catches this regression,
  and it still fires.
- `9d7f83556a` Dropped a dead duplicate `codegenNativeComponent` mock the merge
  left in `test-setup-native.cjs`. Both branches registered a handler for the
  same module id; the first (v3's `() => 'NativeComponent'`, which matches the
  `v3-canary` and `expo-router` setups) shadowed main's, leaving main's
  unreachable.

## Failure attribution

### Fixed here

**`@tamagui/cli` `toTailwindDefaultConfig`.** The drift was a single entry: the
bundle had `bg: 'backgroundColor'`, the v6 runtime config has `bg: 'background'`.
The source change was intentional: `code/core/shorthands/src/v6.ts` says
`bg: 'background'` while `v4.ts` and `v5.ts` both keep `'backgroundColor'`, and
`d1e39772e5 feat(config): align v6 candidate families and names` (2026-07-30) is
the commit that made exactly that swap. v3-beta then added real `background`
support on both platforms (`ac514d949a`, `efe9fb42ac`). So the bundle was stale.

**That bundle has no generator.** A repo-wide search for
`to-tailwind-default-config` finds only the file, its consumer
`src/to-tailwind.ts`, and its test. It is hand-maintained and will drift again
the next time the v6 config moves. Giving it a generator is its own piece of
work.

**`@tamagui/core-test` `_withStableStyle` media expressions.** Fixed by the port
above, plus one test adjustment. main's version asserted `xs` was active via
`mediaQueryDefaultActive`. That seed does not survive on native in v3, correctly:
`test-setup-native.cjs` deletes `IS_STATIC`, so `setupMediaListeners` actually
runs and real dimensions win. A runtime probe showed a 1024x768 window with
`xs`/`sm`/`md` false and `lg`/`xl`/`xxl`/`gtXs`/`gtSm`/`gtMd` true, `gtLg` false,
which is a coherent evaluation. The test still checks all three cases (media
false + condition true, media true + condition true, media true + condition
false) and still expects `[false, true, false]`; it just uses `lg`, a key that is
genuinely active.

## Things that look broken and are not

**`bun run check` exiting 127 on a fresh worktree** is only the workspace bin
link. `./node_modules/.bin/tamagui` does not exist until `@tamagui/cli` has a
`dist`, and a fresh `bun install` runs before the build. `.github/actions/install`
handles this explicitly: install with `--ignore-scripts`, build, then re-run
`bun install` to link workspace bins. Doing the same locally fixes it.

**main's `scripts/cache-npm-webauth.cjs` is correctly absent.** v3's `release.ts`
replaced the entire `npm publish --workspaces` path with the G1 staged-artifact
flow and has its own passkey batching (one interactive publish first, then chunks
of six). Nothing references the helper. Its siblings
`release-npm-registry.ts`, `release-publish-cache.ts`, and
`release-publish-batches.cjs` did come across and are now orphaned; their tests
still pass (9/9) but nothing in the v3 release path imports them.

**Build runs dirty the working tree.** A root build deletes the checked-in
`subpath-only-package/types/feature.d.ts` fixture (its test rebuilds it, so this
is harmless) and rewrites several `tamagui.generated.css` files. The
`next-turbopack` suite additionally rewrites its own `src/` fixtures. Restore
these rather than committing them.

**`@tamagui/core` ships bundled dist that inlines `@tamagui/web`.** Building with
`--filter=@tamagui/web` alone does not propagate: `core/dist/native.cjs` and
`test.native.cjs` keep the old inlined copy, and every test importing
`@tamagui/core` silently loads stale code. Any A/B on a `core/web` source file
must rebuild both packages or it will measure the old artifact and conclude the
change did nothing.
