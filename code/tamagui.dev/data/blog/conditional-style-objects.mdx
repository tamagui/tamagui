<IntroParagraph large>
  Every Tamagui style prop now accepts a flat object for conditional values.
  It is a second spelling of the clause strings v3 introduced, and the two
  render identically:
</IntroParagraph>

```tsx
<View backgroundColor="red hover:blue sm:green sm:hover:purple" />

<View
  backgroundColor={{
    default: 'red',
    hover: 'blue',
    sm: 'green',
    'sm:hover': 'purple',
  }}
/>
```

The object keys are the same modifiers the string form uses. State
(`hover`, `press`, `focus`, `disabled`), your media queries (`sm`, `gtMd`),
theme (`dark`, `light`), platform (`ios`, `android`, `web`, `native`), lifecycle
(`enter`, `exit`), groups (`group-hover`, `group-press/card`), and container
queries (`@sm`, `@sm/card`) all work, and chains join with a colon
(`dark:sm:hover`). `default` is the base value.

### Why a second form

Strings are the shortest way to write one or two conditions, and they stay the
recommended spelling for that. Objects are better at three things:

Values that are not strings. `scale={{ press: 0.98 }}` and
`opacity={{ enter: 0, exit: 0 }}` keep their numbers as numbers.

Values built in code. An object can come from a function or a ternary without
string concatenation:

```tsx
<View backgroundColor={{ default: tone, hover: hoverTone }} />
```

Long condition lists. Past a few clauses, one key per line reads better than
one long string, and your editor autocompletes the keys.

There is no mode to choose. Both forms are always on, and you can mix them
per prop in one component:

```tsx
<View backgroundColor="red hover:blue" scale={{ press: 0.98 }} />
```

### It works everywhere strings do

The object form works on style props, in `styled()` definitions, in variant
branch values, and on variant props themselves:

```tsx
const SizedText = styled(Text, {
  variants: {
    size: {
      md: {
        fontSize: { default: 'sm', gtMd: 'md' },
      },
    },
  } as const,
})

<SizedText size={{ default: 'sm', gtMd: 'md' }} />
```

Enter and exit clauses behave the same as their string forms, including the
implicit resting value: `opacity={{ enter: 0 }}` animates from 0 to the
property's resting value on mount.

### Plain value objects are untouched

Some React Native styles are objects already, like
`shadowOffset={{ width: 0, height: 2 }}`. An object only parses as conditional
when it has a `default` key or its first key is a known modifier chain, so
structured values pass through whole.

### Compiler output is identical

A statically known conditional object compiles to the same atomic CSS as the
equivalent string, byte for byte, with the same class names. Dynamic objects
resolve at runtime through the same path strings use. The runtime cost of the
feature is about 0.2 kB gzipped.

The object form is flat by design. There is no nesting objects inside
breakpoints inside pseudo states. One property, one object, each key a full
condition. Deep validation of keys stays where it already lives, in the
TypeScript types and the compiler.

Available now in v3. See the [styling docs](/docs/intro/styles) for the full
modifier list.
