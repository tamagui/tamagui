<IntroParagraph>
  Tamagui installs with no bundler configuration on web or native. Start small,
  and add the compiler and bundler plugins once the basics work.
</IntroParagraph>

The fastest start is a starter template:

```bash
npm create tamagui@latest
```

<Collapsible id="set-up-with-an-agent" title="Set up with an agent">

Paste this brief into your coding agent for a new project:

```
Add Tamagui v3 to this project. Run `npx tamagui@beta setup` and follow the brief it
prints, adapting it to this project's bundler and framework. Do not skip the
verification step at the end, and tell me anything you had to skip or guess at.
```

For a project that already uses Tamagui v1 or v2:

```
Upgrade this project to Tamagui v3. Run `npx tamagui@beta migrate --from v2` and
follow the brief it prints. Aim for the intermediate checkpoint: V3 APIs with my
existing design values. Identify the package version and config version separately.
If I use Config v5 or v5-subtle, keep it; do not move to Config v6, remap its colors
or scales, or convert the whole app to html.* or Tailwind in this pass.

Run the flat-values codemod in dry-run first, show me the report, and wait for me to
read it before you write anything. Tell me every site the codemod refused and why.
After the required API changes, compare the same screens and interactions against
the baseline. A working V3 app on Config v5 is a completed upgrade. List optional
Config v6 or frontend changes separately; do not begin them automatically.
```

For v1 projects, use `--from v1` to run the v1-to-v2 migration first.

For an app already on v3 with Config v5:

```
This app already uses Tamagui V3 with Config v5. Check what remains of the API
migration before changing anything. Keep Config v5 and our current resolved design
values. Do not rerun completed codemods or adopt Config v6 by default. Validate the
remaining changes in real screens, and report any optional design migration as a
separate follow-up.
```

If you later choose Config v6, start a separate change with its own visual baseline.
The same token name can resolve to a different spacing, font, or color value, and
breakpoint names can change meaning. See
[the staged config migration](/docs/guides/how-to-upgrade#recommended-defer-config-v6-to-its-own-migration).

**Describe your design system.** Generate a reference for your project's tokens,
themes, and components, commit it, and include it in your agent's context:

```bash
npx tamagui@beta generate-prompt
```

**Skills.** If your agent supports
[skills](https://github.com/tamagui/tamagui/tree/v3-beta/skills), install the
Tamagui skills:

```bash
npx skills add https://github.com/tamagui/tamagui/tree/v3-beta/skills
```

`tamagui` covers authoring: `styled()`, variants, flat values, tokens and themes,
animations, and what the compiler does. `tamagui-upgrade-v3` covers the migration:
order, codemod reports, unsupported cases, and verification.

**Check the result.**

- Tokens have no `$` prefix. Conditional values are strings
  (`bg="background hover:background-hover"`) or typed objects
  (`bg={{ default: 'background', hover: 'background-hover' }}`).
- Matching clauses resolve by platform, condition count, then category (media,
  container, theme, group, state).
- Install every `tamagui` and `@tamagui/*` package at the same exact version.
  `tamagui check` finds mismatches.
- Run the app and check tokens, layouts, and interactions in real screens.

</Collapsible>

## Requirements

- **React 19+**
- **TypeScript 5+**
- **React Native 0.81+** with the New Architecture enabled, for native apps.
  Tamagui uses newer style features such as `boxShadow` and `filter`. On web
  there are no version restrictions.

## Install

Install the full UI kit:

```bash
yarn add tamagui @tamagui/config
```

Or install only the style library. The `tamagui` package is a superset of
`@tamagui/core`, so anywhere the docs reference core you can use either:

```bash
yarn add @tamagui/core @tamagui/config
```

## Choose a styling frontend

Tamagui has two ways to write styles. Both produce the same output, and the
choice is per import path, so you can mix them later. Pick one to start.

<MDXTabs.Content value="props">

Typed style props on semantic `html.*` elements. This is the recommended base
for new apps. It reads like React Native, stays close to the web, and needs no
extra package.

```tsx fileName="App.tsx"
import { TamaguiProvider, createTamagui, html } from 'tamagui'
import { defaultConfig } from '@tamagui/config/v6'

const config = createTamagui(defaultConfig)

declare module 'tamagui' {
  interface TamaguiCustomConfig extends typeof config {}
}

export default () => (
  <TamaguiProvider config={config} defaultTheme="light">
    <html.div width={200} height={200} backgroundColor="background" />
  </TamaguiProvider>
)
```

Continue with [Components](/docs/intro/components) and
[Styling](/docs/intro/styles).

</MDXTabs.Content>

<MDXTabs.Content value="tailwind">

Tailwind utility classes on `className`, extracted to atomic CSS on web and
resolved to native styles on iOS and Android.

```bash
yarn add @tamagui/tailwind
```

```tsx fileName="App.tsx"
import { TamaguiProvider, createTamagui } from 'tamagui'
import { html } from '@tamagui/tailwind'
import { defaultConfig } from '@tamagui/config/v6'

const config = createTamagui(defaultConfig)

declare module 'tamagui' {
  interface TamaguiCustomConfig extends typeof config {}
}

export default () => (
  <TamaguiProvider config={config} defaultTheme="light">
    <html.div className="w-[200px] h-[200px] bg-background" />
  </TamaguiProvider>
)
```

Continue with [Tailwind](/docs/core/tailwind).

</MDXTabs.Content>
</MDXTabs>

You usually export the config from a `tamagui.config.ts` file. See
[Configuration](/docs/core/configuration) for what goes in it.

Set your root theme with the `defaultTheme` prop on `TamaguiProvider` rather
than wrapping the app in `<Theme>`. That keeps the
[`fastSchemeChange` setting](/docs/core/settings) working on native and lets
light and dark switch through media queries during SSR on web.

That is the whole setup:

<Preview>
  <DemoButton />
</Preview>

```tsx class=preview line=5
import { Button } from 'tamagui'

export default function Demo() {
  return <Button theme="blue">Hello world</Button>
}
```

Every feature works at runtime, so nothing above depends on a bundler plugin.
When you are ready for production, [set up the compiler](/docs/intro/compiler-install)
for smaller bundles and faster renders.
