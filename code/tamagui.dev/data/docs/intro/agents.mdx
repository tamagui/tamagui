title: Set up with an agent
description: Install or upgrade Tamagui with a coding agent
---

## New project

Paste this brief into your coding agent:

```
Add Tamagui v3 to this project. Run `npx tamagui@beta setup` and follow the brief it
prints, adapting it to this project's bundler and framework. Do not skip the
verification step at the end, and tell me anything you had to skip or guess at.
```

## Upgrading from v1 or v2

For a project that already uses Tamagui:

```
Upgrade this project to Tamagui v3. Run `npx tamagui@beta migrate --from v2` and
follow the brief it prints. Aim for the intermediate checkpoint: V3 APIs with my
existing design values. Identify the package version and config version separately.
If I use Config v5 or v5-subtle, keep it; do not move to Config v6, remap its colors
or scales, or convert the whole app to html.* or Tailwind in this pass.

Run the flat-values codemod in dry-run first, show me the report, and wait for me to
read it before you write anything. Tell me every site the codemod refused and why.
After the required API changes, compare the same screens and interactions against
the baseline. A working V3 app on Config v5 is a completed upgrade. List optional
Config v6 or frontend changes separately; do not begin them automatically.
```

For v1 projects, use `--from v1` to run the v1-to-v2 migration first.

### Already on V3 with Config v5

Config v5 is supported on v3. To resume an upgrade:

```
This app already uses Tamagui V3 with Config v5. Check what remains of the API
migration before changing anything. Keep Config v5 and our current resolved design
values. Do not rerun completed codemods or adopt Config v6 by default. Validate the
remaining changes in real screens, and report any optional design migration as a
separate follow-up.
```

If you later choose Config v6, start a separate change with its own visual baseline.
The same token name can resolve to a different spacing, font, or color value, and
breakpoint names can change meaning. See [the staged config migration](/docs/guides/how-to-upgrade#recommended-defer-config-v6-to-its-own-migration).

Review the codemod report and verify the app in real screens before completing the
upgrade.

## Describe your design system

Generate a reference for your project's tokens, themes, and components:

```bash
npx tamagui@beta generate-prompt
```

This writes `tamagui-prompt.md`. Commit it and regenerate it when your config changes.
Include it in your agent's context.

## Skills

If your agent supports [skills](https://github.com/tamagui/tamagui/tree/v3-beta/skills),
install the Tamagui skills:

```bash
npx skills add https://github.com/tamagui/tamagui/tree/v3-beta/skills
```

- **`tamagui`** covers authoring: `styled()`, variants, flat values, tokens and themes,
  animations, and what the compiler does.
- **`tamagui-upgrade-v3`** covers the migration: migration order, codemod reports,
  unsupported cases, and verification.

## Check the result

- **Use v3 syntax.** Tokens have no `$` prefix. Write conditional values as strings
  (`bg="background hover:background-hover"`) or typed objects
  (`bg={{ default: 'background', hover: 'background-hover' }}`).
- **Check condition precedence.** Matching clauses resolve by platform, condition
  count, then category (media, container, theme, group, state).
- **Keep package versions aligned.** Install every `tamagui` and `@tamagui/*` package
  at the same exact version. Run `tamagui check` to find mismatches.
- **Run the app.** Check tokens, layouts, and interactions in real screens.
