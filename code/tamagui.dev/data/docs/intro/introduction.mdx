## Two ways to write styles

Tamagui ships two styling frontends. Both compile to the same atomic CSS on web
and the same native styles on iOS and Android, and both accept the same tokens,
themes, and media queries.

**Style props** on the `html.*` elements are the recommended base. They are
typed, they read like React Native, and they stay close to the web:

```tsx
import { html } from 'tamagui'

export const Card = () => (
  <html.article padding="4" borderRadius="lg" backgroundColor="background">
    <html.h2 fontSize="6">Hello</html.h2>
    <html.p color="color-11 hover:color-12">World</html.p>
  </html.article>
)
```

**Tailwind** classes on `className` are the other option, for teams who already
think in utilities:

```tsx
import { html } from '@tamagui/tailwind'

export const Card = () => (
  <html.article className="p-4 rounded-lg bg-background">
    <html.h2 className="text-2xl">Hello</html.h2>
    <html.p className="text-color-11 hover:text-color-12">World</html.p>
  </html.article>
)
```

The choice is per import path, so one app can use both. Read
[Components](/docs/intro/components) for the style prop path and
[Tailwind](/docs/core/tailwind) for the utility path.

## Why a compiler

Cross-platform apps live inside a trilemma. Pick two of: an app that feels
native, one codebase for native and web, and shipping fast.

React Native shares logic between platforms and asks you to write views twice
for the best result. React Native Web pushed the shared line further up the
tree, but on the web its styles stay in JavaScript. Media queries, themes, and
interactive styles run as hooks that touch every component, so pages re-render
more than they should and bundles grow with every screen.

Tamagui moves that line again with an optimizing compiler, `@tamagui/static`.
It reads your components at build time and:

The `Text` became a `p` and the `YStack` became a `div`. On native the same
pass produces `Text` and `View`. Flattening is where most of the speed comes
from. Across real apps around a third to a half of components flatten, and the
result on web is close to hand-written CSS. On native the output is within a
few percent of hand-optimized React Native, with the whole feature set intact.

Everything still works at runtime. The compiler is an optimization you can add
later, and a component it cannot optimize simply renders the normal way. See
[Benchmarks](/docs/intro/benchmarks) for numbers and
[Compiler installation](/docs/intro/compiler-install) to turn it on.
