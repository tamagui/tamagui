description: Reproducible web and native performance comparisons

Compiled Tamagui Tailwind mounted faster than NativeWind and Uniwind in every
measured web scenario. Tailwind CSS was faster than Tamagui in most web cells.
On the native class fixture, Uniwind was faster than NativeWind in every
measured cell. The native Tamagui fixtures differ, so this run cannot support a
Tamagui versus NativeWind or Uniwind ranking.

These results were recorded on September 1, 2026 HST. They measure one set of
fixtures on one machine. They are useful for finding costs in those fixtures,
not for ranking every application.

## Web results

The web fixture renders 200 items, or 60 in the heavy case. Mount starts with an
empty root. Update changes the fixture state without replacing the root.
Remount removes and recreates the tree. Timing starts before the React state
change and ends in `useLayoutEffect`.

Each production build ran in Chromium 151.0.7922.34 on an Apple M5 Pro with 18
logical CPUs and 64 GiB of memory. The runner used Bun 1.3.14 on Darwin 25.5.0.
Two warmup rounds preceded 10 retained rounds. Seed `73129` reshuffled the
framework and scenario order. A behavior gate passed all 50 framework and
scenario cases before timing.

Simple, rich, group, and heavy use Tamagui `3.0.0-beta.901.1`. Animated uses
`3.0.0-beta.917.1`, which flattened all 14 compiler candidates with zero
bailouts. The other pinned versions are Tailwind CSS `4.3.0`, NativeWind
`5.0.0-preview.4`, React Native Web `0.21.2`, Uniwind `1.11.0`, React `19.2.3`,
and React DOM `19.2.3`.

All values are mean milliseconds. Lower is faster.

Tamagui Tailwind had lower mount means than NativeWind and Uniwind in all five
scenarios. The paired 95% confidence intervals were below zero for each of
those 10 comparisons. In the animated fixture, Tamagui also had lower remount
means than both. Its update difference from NativeWind and Uniwind was not
resolved by the paired intervals.

Tailwind CSS had lower means than Tamagui Tailwind for 10 of the 15 cells.
Inline React was lower for simple, rich, group, and animated updates.
Uniwind was lower than Tamagui Tailwind for animated update. The group mount
and remount means favored Tamagui over Tailwind CSS, while their paired
intervals did not resolve a difference.

This is the utility-syntax comparison, so the Tamagui arm uses
`@tamagui/tailwind`. It does not measure the broader component APIs.

## Native results

The native campaign used standalone Release apps with embedded production
bundles. It ran on an iOS 26.4 simulator hosted by the same Apple M5 Pro. Two
warmup rounds preceded 12 retained rounds, with the same seed and a machine-load
gate. All apps used Expo `57.0.15`, React `19.2.3`, and React Native `0.86.2`.
The shared class arms used Tailwind CSS `4.3.0`.

NativeWind and Uniwind share a byte-identical class fixture and passed the same
20 by 20 layout gate. NativeWind also used `react-native-css` `3.0.7`,
React Native Reanimated `4.5.1`, and React Native Worklets `0.10.1`. All values
are mean milliseconds.

| Scenario | Library       |  Mount | Update | Remount |
| -------- | ------------- | -----: | -----: | ------: |
| Simple   | NativeWind v5 |  93.27 |  51.20 |  101.66 |
| Simple   | Uniwind       |   3.05 |   2.81 |    3.56 |
| Themed   | NativeWind v5 |  49.27 |  27.45 |   40.47 |
| Themed   | Uniwind       |   3.36 |   2.87 |    3.32 |
| Rich     | NativeWind v5 | 159.10 |  67.43 |  143.32 |
| Rich     | Uniwind       |   3.55 |   3.03 |    3.87 |
| Group    | NativeWind v5 | 344.18 | 126.82 |  259.79 |
| Group    | Uniwind       |  11.95 |   8.36 |   12.42 |
| Heavy    | NativeWind v5 | 141.29 |  86.27 |  165.18 |
| Heavy    | Uniwind       |   6.63 |   3.94 |    6.88 |

Uniwind had lower means in every native cell. NativeWind's confidence intervals
were wide, so the table should not be read as a precise estimate of its typical
cost.

The Tamagui runtime and compiled native arms use different fixture families.
They verify Tamagui's runtime and compiler paths, but they are not comparable to
the class fixture above. A valid native Tamagui versus NativeWind and Uniwind
comparison still needs one byte-identical fixture and one measurement boundary
for all three libraries.

## Source record

The cross-framework harness began in `code/comparisons`. It was extracted from
this monorepo in [commit `300a4db8de`](https://github.com/tamagui/tamagui/commit/300a4db8def094229793e2c416b1a008fc5d20a5)
so NativeWind does not enter the main workspace dependency graph. The monorepo
still contains its conformance harness, runtime microbenchmarks, compiler graph
benchmark, bundle checks, and Tamagui browser fixture.

The source values above come from committed result files in the extracted
comparison repository. The full web receipt is commit `8b45f79809`, the
animated receipt is `9896f9c488`, and the native receipt is `325483b1b9`. The
current summary is commit `bd0c96e`. That repository has no public remote yet,
so the raw receipts cannot currently be linked from this page. The same web
table is retained in the [Tamagui Tailwind post](/blog/tailwind-mode).

## What this does not measure

- The web run covers production rendering after the page is loaded. It does not
  measure server rendering, hydration, interaction latency, or network cost.
- The native run uses one simulator. It does not measure physical-device
  startup, memory, GPU work, energy use, or Android.
- Compiler acceptance and correct pixels are separate questions. The behavior
  gates cover these benchmark fixtures. They do not prove visual equivalence
  for every utility.
- Small timing differences can move with hardware, browser, operating system,
  and application shape. Direct claims above use the paired receipts.
- Bundle size and build time are tracked by the harness but omitted here. They
  need their own comparison because each tool ships a different amount of
  runtime and compiler code.
